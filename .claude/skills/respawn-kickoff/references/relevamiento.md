# Árbol del relevamiento

> Referencia de `respawn-kickoff`: las preguntas de cada bloque, de dónde se
> averigua cada dato antes de preguntar y qué ramas abre cada respuesta. Cada
> pregunta se hace sola, con una lectura propuesta.

## Contenido

1. Antes de preguntar
2. El negocio
3. El visitante
4. La acción objetivo
5. El material real
6. Quién actualiza
7. Plazos
8. Ramas
9. Cuándo cerrar

## 1. Antes de preguntar

Se mira lo que existe y se anota lo que se encontró. Lo encontrado no se
pregunta: se confirma dentro de la lectura propuesta.

| Dónde mirar                              | Qué suele estar                                              |
| ---------------------------------------- | ------------------------------------------------------------ |
| La web actual del negocio, si tiene      | Servicios, textos, fotos, datos de contacto                  |
| Sus redes                                | Cómo habla, qué publica, fotos reales, horarios              |
| Su ficha en mapas                        | Dirección, horario, reseñas reales, fotos del local          |
| El material que hay en el proyecto       | Logo, fotos, listas de precios, mensajes del cliente         |
| Lo que el usuario ya contó en la conversación | El pedido original y su contexto                        |

- Un dato tomado de una de estas fuentes se anota con su origen.
- Si las fuentes se contradicen, se pregunta cuál vale.
- Las reseñas reales no se copian al sitio sin permiso del cliente.

## 2. El negocio

| Pregunta                                                  | Completa en el brief        | Lectura propuesta desde                    |
| --------------------------------------------------------- | --------------------------- | ------------------------------------------ |
| ¿Qué hace el negocio, dicho como lo dice el dueño?        | Qué es                      | Redes y web actual                         |
| ¿Dónde está y qué zona atiende?                           | Dónde                       | Ficha en mapas                             |
| ¿Qué dice el dueño que lo hace distinto?                  | Qué lo distingue            | Lo que repite en sus publicaciones         |
| ¿Cómo consigue clientes hoy?                              | Cómo consigue clientes      | Lo que contó el usuario                    |
| ¿Qué no hace o no quiere ofrecer?                         | No incluye                  | Sin fuente: se pregunta                    |

- «Qué lo distingue» tiene que ser un hecho. Si la respuesta es «calidad y
  buena atención», se vuelve a preguntar por un ejemplo concreto.
- Lo que el negocio no ofrece importa tanto como lo que ofrece: evita textos
  que prometen de más.

## 3. El visitante

| Pregunta                                                          | Completa en el brief     |
| ----------------------------------------------------------------- | ------------------------ |
| ¿Quién entra a la web: quién es y qué edad tiene?                 | Quién entra              |
| ¿Desde dónde llega: redes, buscador, un link que le pasan?        | Quién entra              |
| ¿Qué quiere saber antes de escribir?                              | Qué quiere saber         |
| ¿Qué pregunta la gente siempre por mensaje?                       | Qué quiere saber         |
| ¿Qué lo hace dudar o irse?                                        | Qué lo frena             |

- Las preguntas que el negocio recibe todos los días son la fuente de las
  preguntas frecuentes del sitio.
- Si hay más de un tipo de visitante, se anota cada uno y cuál pesa más.

## 4. La acción objetivo

| Pregunta                                                        | Completa en el brief            |
| --------------------------------------------------------------- | ------------------------------- |
| ¿Qué tiene que hacer el visitante al final?                     | Qué tiene que hacer             |
| ¿Por qué canal: WhatsApp, llamada, compra, turno?               | Canal                           |
| ¿Qué número o qué casilla recibe los contactos y quién lo atiende? | Canal                        |
| ¿En qué horario se responde?                                    | Canal                           |

- La lectura propuesta de fábrica es WhatsApp, porque es lo que usa casi todo
  negocio local. Se confirma, no se da por hecha.
- Una sola acción principal. Si el dueño quiere tres, se le pide elegir.

## 5. El material real

| Pregunta                                                     | Completa en el brief   |
| ------------------------------------------------------------ | ---------------------- |
| ¿Hay logo? ¿En qué formato?                                  | Material real          |
| ¿Hay fotos propias del local, del trabajo y de las personas? | Material real          |
| ¿Hay textos escritos o hay que armarlos con lo que cuente?   | Material real          |
| ¿Hay lista de productos o servicios, con sus precios?        | Material real          |
| ¿Se muestran los precios en la web?                          | Material real          |
| ¿Hay reseñas reales que se puedan usar, con permiso?         | Material real          |

- Lo que no existe se anota como faltante con quién lo consigue: el cliente,
  o un trabajo aparte.
- Si no hay fotos propias, se dice ahí mismo que el sitio no usa fotos de
  banco: o se consiguen, o esa sección no va.
- Quién escribe los textos y quién saca las fotos se pregunta. No se da por
  incluido ni por excluido.

## 6. Quién actualiza

Este bloque decide si el proyecto lleva panel y, si lo lleva, qué forma tiene
cada formulario.

| Pregunta                                                           | Completa en el brief            |
| ------------------------------------------------------------------ | ------------------------------- |
| ¿Qué va a cambiar después de publicar: precios, fotos, horarios?   | Quién actualiza el contenido    |
| ¿Cada cuánto cambia cada cosa?                                     | Quién actualiza el contenido    |
| ¿Quién lo va a cambiar: el dueño, un empleado, Respawn?            | Quién actualiza el contenido    |
| ¿Desde dónde: celular o computadora?                               | Quién actualiza el contenido    |

- Cada tarea queda como una fila: qué se cambia, quién y cada cuánto.
- Si el dueño quiere cambiar algo solo, el proyecto necesita panel. Se marca
  en el momento si eso se sale del paquete pedido.
- Si los cambios los hace Respawn, es mantenimiento mensual.

## 7. Plazos

| Pregunta                                                  | Completa en el brief |
| --------------------------------------------------------- | -------------------- |
| ¿Hay una fecha que importa: apertura, temporada, evento?  | Entrega acordada     |
| ¿Cuándo puede el cliente entregar el material?            | Depende de           |
| ¿Quién aprueba el trabajo y cuánto tarda en responder?    | Depende de           |

- Una fecha de entrega depende siempre de la fecha del material. Se anotan
  las dos.

## 8. Ramas

Cada respuesta puede abrir una rama. Sus preguntas se hacen recién cuando la
rama se abre.

| Se abre cuando…                          | Preguntas de la rama                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| Hay panel                                | Cuántas personas entran; si todas pueden hacer lo mismo; qué tarea hacen más seguido       |
| Hay catálogo                             | Cuántos productos; si tienen variantes; quién hace la carga inicial; si cambia el stock    |
| Se cobra en línea                        | Si el cliente tiene cuenta de Mercado Pago y a nombre de quién; cómo entrega; si hace envíos; quién atiende los pedidos |
| Hay turnos o reservas                    | Cuánto dura cada uno; quién los atiende; si se pueden cancelar; qué pasa si se superponen  |
| Hay usuarios con distintos permisos      | Qué puede cada uno; qué no tiene que ver cada uno                                          |
| Se juntan datos de personas              | Qué datos; para qué; quién los ve; cuánto se guardan                                       |
| Hay suscripciones o pagos que se repiten | Cómo se da de baja; qué pasa con lo ya pagado                                              |
| El negocio ya tiene dominio o web        | A nombre de quién está el dominio; quién tiene el acceso; qué pasa con la web vieja        |
| Hay otro sistema en uso                  | Qué sistema; si hay que traer datos; si tienen que conectarse                              |

- Las ramas de cobro, de datos personales y de suscripciones traen
  obligaciones legales. Se anotan en el alcance para que la auditoría las
  compruebe.
- La rama de dominio se pregunta siempre: quién lo tiene registrado decide si
  el cliente es dueño de su sitio.

## 9. Cuándo cerrar

El relevamiento termina cuando se cumple todo esto:

- Cada campo del brief tiene su dato o su `[FALTA: …]`.
- Cada faltante dice quién lo consigue.
- Las ramas abiertas tienen sus respuestas o sus faltantes.
- Todo lo que cruzó el límite de un paquete se dijo y se resolvió.
- El usuario leyó el brief armado y lo confirmó.

Si quedan más de cinco faltantes que frenan el diseño, el próximo paso no es
diseñar: es llevarle las preguntas al cliente.
